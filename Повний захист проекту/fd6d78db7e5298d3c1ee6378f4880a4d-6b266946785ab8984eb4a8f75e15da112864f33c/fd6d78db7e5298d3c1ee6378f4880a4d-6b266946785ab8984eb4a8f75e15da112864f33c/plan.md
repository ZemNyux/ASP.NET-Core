- Формування команд (по 2–4 особи залежно від складності проєкту), визначення назви команди, ролей учасників команди

- Первинне вивчення можливостей і вимог до обраного проєкту https://gist.github.com/sunmeat/27caafa2ff5b637879cd95e3de9c3081
- Огляд технологій, які можна використовувати в ASP.NET Core
- Розробка Software Requirements Specification (SRS) для проєкту: визначення набору функціональностей, вимог, термінів https://gist.github.com/sunmeat/db7033e5d5ac357533d630409aa08c12
- Визначення ключових компонентів проєкту
- Пошук макетів та референсів https://gist.github.com/sunmeat/1fcb19f74f1de099c1050aa94609bf5a

## 2 тиждень - SPRINT 1 (24.08 - 30.08): Проєктування архітектури системи
- Проєктування архітектури системи з урахуванням SRS (структура бекенду, фронтенду, БД - у форматі скрінів)
- Створення UML-діаграми класів для опису основних сутностей і зв'язків між ними
- Обговорення архітектурних патернів та патернів проєктування, які підходять для проєкту

## 3 тиждень - SPRINT 2 (31.08 - 06.09): Початок розробки
- Вступ до методології SCRUM: розподіл ролей (Product Owner, Scrum Master, Development Team) і обов'язків у команді, планування спринтів, додавання завдань в беклог, робота з канбан-дошкою на Youtrack / Jira / Trello
- Створення базової структури проєкту ASP.NET Core (поки що можна БЕЗ розділу на 3-4 проєкти в солюшені)
- Встановлення та налаштування необхідних інструментів та бібліотек
- Реалізація початкових класів і модулів відповідно до архітектури проєкту
- Планування та запуск другого SCRUM-спринту: додавання завдань до загального беклогу задач та формування задач на поточний тиждень

## 4 тиждень - SPRINT 3 (07.09 - 13.09): Робота з базами даних та базова функціональність
- Вибір СУБД для проєкту (бажано Firebase / Postgres / MongoDB)
- Підключення EF Core для взаємодії з базою даних
- Створення бази даних, проєктування таблиць (Code First / Database First)
- Реалізація основних методів для створення, читання, оновлення та видалення даних (CRUD) через класи-репозиторії
- Початок розробки ключових функціональностей проєкту відповідно до SRS

## 5 тиждень - SPRINT 4 (14.09 - 20.09): Розробка інтерфейсу користувача
- Розробка користувацького інтерфейсу з використанням React / ASP.NET Core (Razor Pages / Blazor)
- Реалізація функціональності взаємодії користувача з системою (запити відправляються fetch, є запити до БД)
- Проєктування та ручне тестування UI / UX
- Застосування патернів проєктування для створення модульної структури (налаштування зв'язків між проєктами)

## 6 тиждень - SPRINT 5 (21.09 - 27.09): Завершення основної функціональності
- Завершення основних модулів проєкту
- Реалізація функціональності, пов'язаної з керуванням даними та взаємодією з користувачем
- Тестування окремих компонентів системи в рамках SCRUM-спринту
- Робота над покращенням продуктивності проєкту
- Підтримка модульності та гнучкості системи

## 7 тиждень - SPRINT 6 (28.09 - 04.10): Додаткові можливості та тестування
- Розробка додаткових функцій, описаних у SRS
- Написання юніт- та інтеграційних тестів для ключових компонентів проєкту з використанням xUnit / NUnit (бажане покриття тестами 60-80%+)
- Виправлення помилок і оптимізація коду в командному режимі
- Рефакторинг і вдосконалення архітектури системи, якщо необхідно (продемонструвати прогрес у SCRUM-ретроспективі)

## 8 тиждень - SPRINT 7 (05.10 - 11.10): Документація, оптимізація та деплой
- Складання технічної документації проєкту
- Оформлення README.md-файла в репозиторії (список пунктів: https://gist.github.com/sunmeat/5b4d38b2277b5c13c0e4857f07c34c9d)
- Створення коментарів документації до ключових компонентів системи (основні публічні класи та публічні методи)
- Сирцевий код обробити в програмах накшталт DocFX / Doxygen, отримати сайт з навігацією, покласти його в папку docs репозиторію
- Цей сайт з документацією викласти на Github Pages / Netlify / Vercel
- Створити документацію по енд-поінтах через Scalar / Swashbuckle, з публікацією
- Оптимізація коду для підвищення продуктивності
- Проведення повного тестування системи
- Виправлення виявлених помилок і багів
- Деплой проєкту
- Додати в рідмі посилання: а) на задеплоєний фронтенд, б) на сайт з документацією по коду, в) на сайт з документацією по енд-поінтам
- Скинути в коментар до ДЗ посилання на рідмі файл
